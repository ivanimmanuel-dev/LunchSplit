# Assignment 1 Reflection


## Start (New Habits to Adopt)

I want to start future assignments by writing down the expected results and edge cases before coding. Trying to figure them out as I coded was time-consuming. C# was new to me, so things like `decimal`, exceptions, and lists took time to understand. Working through one failing test at a time made the bill-splitting logic easier to follow, especially when I got to rounding and making sure every cent was accounted for. I also joined the course late, which made it harder to get oriented. Next time, I want to plan the basic structure and important edge cases earlier so I have a clearer direction while implementing them.


## Stop (Bad Habits to Break)

I want to stop assuming every red error means the calculation is wrong. Some of my problems were simpler: parameter names didn’t match, or a method was outside its class. When I get an error, I’ll read the first message, check the names and braces, and rerun the test before changing more code. I also thought following the assignment tests step by step would make everything straightforward. Later tests affected code I had already written, so I need to keep the overall behavior in mind as I work through individual cases.


## Continue (Good Habits to Reinforce)

I want to continue using small red-green-refactor steps in Visual Studio. Seeing a test fail for the expected reason, making it pass, and rerunning older tests helped me trust changes to `Splitter` and `Rounder`. I also want to keep making meaningful commits as features are completed. The tests were most useful when I understood why an answer should be correct. Thinking through the expected behavior before writing each test helped me a lot during the assignment. My familiarity with GitHub, Git, and Visual Studio helped me keep the project organized while I learned C#.
